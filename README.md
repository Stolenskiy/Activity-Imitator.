# Activity Imitator

Утиліта, яка імітує людську активність (рух миші, кліки, скрол, навігаційні клавіші) під час довгих автоматизованих тестів у IDE, щоб віддалена сесія (VDI/RDP) або сама IDE не завершувалась через тайм-аут бездіяльності.

## Вимоги

- Python 3.10+
- Linux із доступом на запис до `/dev/uinput`. На сучасних десктопах (systemd-logind) його автоматично отримує користувач, який сидить за комп'ютером; перевірити: `getfacl /dev/uinput`
- Для гарячих клавіш і автопаузи потрібен доступ на читання до `/dev/input/*`: користувач має бути в групі `input`
- Працює і на Wayland, і на X11; XWayland/`DISPLAY` не потрібні

## Встановлення

Система (Debian/Ubuntu/Pop!_OS) блокує `pip install` поза віртуальним середовищем (PEP 668), тож використовуйте venv:

```bash
sudo usermod -aG input $USER                      # гарячі клавіші й автопауза (evdev)
# перелогіньтесь (вийти з сесії / зайти знову), щоб членство в групі 'input' набуло сили
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt   # включно з PySide6 для GUI
```

> **Чому uinput, а не pyautogui/XTest:** на Wayland (COSMIC, GNOME) XWayland пропускає емуляцію введення через портал «Віддалене керування» і питає дозволу при кожному запуску (як «Невідомий застосунок»). Віртуальні пристрої uinput створюються на рівні ядра: композитор бачить їх як звичайну мишу й клавіатуру, тож жодних діалогів немає. Вказівник абсолютний, і COSMIC відображає його координати на монітор, де зараз курсор.
>
> **Чому evdev, а не X11-хук:** на Wayland-сесіях (GNOME, Cosmic тощо) композитор навмисно не віддає глобальні події клавіатури X11/XWayland-клієнтам — тому бібліотеки на кшталт `pynput` з X11-бекендом мовчки нічого не ловлять. `evdev` читає сирі події напряму з `/dev/input` (без ексклюзивного захоплення пристрою, тож інші застосунки й далі отримують ці ж клавіші як зазвичай).

## Запуск

**Графічний інтерфейс** (рекомендовано; ярлик «Activity Imitator» на робочому столі запускає саме його):

```bash
.venv/bin/python activity_imitator_gui.py
```

- велика кнопка-кільце запускає й зупиняє імітацію, по колу видно відлік до наступної дії;
- статус (Активний / Автопауза / Пауза / Зупинено), остання дія, час роботи, кількість дій;
- **автопауза**: щойно ви торкаєтеся миші, тачпада чи клавіатури, імітація стає на паузу й продовжується сама після N секунд бездіяльності (за замовчуванням 60 с, налаштовується);
- таймер тривалості (∞, 30 хв – 8 год) з автозупинкою;
- журнал подій і налаштування: інтервал між діями, типи дій, автозапуск, згортання в трей;
- іконка в треї з кольоровим індикатором статусу; закриття вікна не зупиняє роботу (вихід — через меню трею);
- повторний запуск ярлика просто показує вже відкрите вікно;
- кліки й клавіші, які надходять одразу після власних дій імітатора, вікно ігнорує, тож імітатор не натисне власні кнопки.

Налаштування зберігаються в `~/.config/activity-imitator/settings.json`.

**Консольний режим** (як раніше):

```bash
.venv/bin/python activity_imitator.py
```

## Гарячі клавіші

- `Ctrl+Alt+S` — пауза / відновлення (у GUI: якщо зупинено — запуск)
- `Ctrl+Alt+Q` — вихід (у GUI: зупинка імітації, програма лишається в треї)
- Будь-який рух миші чи натискання клавіші — автопауза (замість старого fail-safe «курсор у кут», який на Wayland не працював надійно)

## Безпека

- Курсор рухається лише в центральній зоні екрана (15–85% ширини/висоти), щоб не зачепити системний трей, панель задач чи кнопки вікон.
- Використовуються лише навігаційні/немодифікуючі клавіші (`Shift`, `Ctrl`, `Alt+←/→`, `Page Up/Down`, `↑/↓`, `Esc`) — жодних `Enter`, `Backspace`, `Delete`, `Space` чи алфавітно-цифрових символів, тобто вміст файлів не змінюється.
- Затримки між діями випадкові (5–45 с), без фіксованого періоду.
- Імітатор не «бореться» з вами за мишу: якщо ви берете її посеред руху, рух переривається.
- Власні віртуальні пристрої (`Activity Imitator virtual …`) слухач ігнорує, тож імітація не сприймається як ваша активність.

## Структура коду

- `RandomizationEngine` — випадкові затримки та вибір дії за вагами
- `UInputBackend` — віртуальні миша (абсолютні координати) і клавіатура через `/dev/uinput`
- `InputSimulator` — рух миші по кривій Безьє, кліки/скрол, навігаційні клавіші
- `SafetyListener` — гарячі клавіші паузи/виходу та час останньої активності користувача для автопаузи (evdev, пасивне читання `/dev/input`, автоматично підхоплює нові пристрої)
- `MainLoop` — головний цикл, консольні логи з таймстемпами
- `activity_imitator_gui.py` — GUI на PySide6 (Qt6): `ImitatorWorker` запускає ті самі класи у фоновому потоці, `MainWindow` показує стан

## Версії й відкат

Проєкт під git; ключові версії позначено тегами:

- `v1-console` — початкова консольна версія (pyautogui);
- `v2-gui-xtest` — GUI, введення ще через pyautogui/XWayland (з діалогом «Віддалене керування»);
- `v3-uinput` — введення через uinput + автопауза.

Повернутися до версії: `git checkout v2-gui-xtest -- .` (або `git switch --detach v2-gui-xtest` для перегляду). Для старих версій потрібен ще `pyautogui` у venv.
